A data warehouse answers analytics questions: totals by day, top products by region, how a metric changed over a year. It stores tables **by column**, compressed, so a query that needs three columns out of fifty reads only those three. It is built to scan billions of rows quickly, not to fetch one row in a millisecond.

A query's time is mostly bytes scanned divided by the scan rate, plus a fixed overhead for planning and start-up, plus a little for each file it opens. When the data lives in a **lakehouse table** upstream, the table's layout decides how much is scanned: partitions let a query on the last day skip the rest, and many small files add overhead. The simulator models this: the scan, the per-file cost, partition pruning, a number of concurrent queries per cluster with a queue behind it, and a result cache that answers a repeated query almost at once.

Warehouses sit off the request path. They are fed by batch jobs, connectors or streams, and they serve analysts and dashboards. When a user-facing page needs an analytics number, the usual answer is to compute it in the warehouse on a schedule and serve it from a cache or a SQL table.

**How the simulator bills this.** Snowflake costs $1,460 per cluster a month (an X-Small warehouse: one credit an hour at $2, for 730 hours), billed only while the cluster runs, since an idle one auto-suspends after `auto_suspend_s`. Databricks SQL works the same way at $1,000 a month. BigQuery has no cluster fee and bills $6.25 per terabyte scanned. Redshift costs $182 per node a month and ClickHouse $250 per node (teaching prices; source to be confirmed).
